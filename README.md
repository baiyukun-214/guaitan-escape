# 怪谈逃生指南 ·《夜班来电》

一个可以完整玩到结算的中文三人合作推理网页游戏。React + TypeScript + Vite，Node + Express + Socket.IO，服务端权威状态机、文件持久化。原创虚构剧本，不改编《恶魔法典》，也未使用该视频内容。

> **当前默认是“离线试玩主持（非AI）”。** 没有配置、调用任何真实付费AI，没有部署到公网。离线版本用明确标识的关键词练习判定，不能冒充语义理解。配置你选择的 OpenAI-compatible 服务后才启用真正LLM叙述和语义标注。

## 运行

需要 Node.js 22.12+（本次测试 Node 24.22.1）、npm。

```bash
npm ci
cp .env.example .env
npm run dev
```

- 网页：`http://localhost:5173`
- 后端：`http://localhost:3001/api/health`
- Vite 将 `/api` 和 `/socket.io` 同源代理到3001；不要直接打开HTML文件。
- `npm run typecheck` 类型检查；`npm test` 非GUI单测及真实HTTP/Socket集成；`npm run build` 生成前端 `dist/`。
- 非开发预览：先 `npm ci && npm run build`，然后 `NODE_ENV=production npm start`，浏览 `http://localhost:3001`。本版运行服务器使用 `tsx`，不要用 `npm ci --omit=dev` 后直接运行。
- 生产模式始终关闭开发沙盒创建和旧沙盒认证。真实房间没有切换他人身份的接口。

## 三人局域网联机

1. 在同一台电脑上运行上述开发命令。三人设备连接同一可信局域网。
2. 在主机查到其局域网IP，例如 `192.168.1.20`，三台设备均打开 `http://192.168.1.20:5173`。必要时仅对该可信局域网放行TCP5173；后端经同源代理，无需对外开放3001。
3. 房主填昵称创建“三人接线台”，把六位房间码告诉另外两人。队友填昵称和房间码加入。每人一台设备或独立浏览器配置；同一浏览器共享本地身份。
4. 各自选择装备，房主指定单人搜证者，另外两位自动成为双人组。房主开始。
5. 微信等外部语音沟通；本站不提供音视频。线索在手牌中，主动“公开给队友”才会共享。
6. 刷新/断线会用该浏览器本地保存的令牌恢复原席位；不要清除浏览器存储、分享令牌或点击“退出”再期望无令牌回原房。服务器重启后仍能读存档；正在计时的轮次重开、未确认扣血提议取消，不会偷偷扣血。

> 这里的 `localhost` 是运行项目那台电脑，不是用户的Mac。盒子中的网页没有自动公网入口；请勿把盒子内网地址当作用户可访问链接。局域网步骤适用于以后把整个项目拿到同一局域网主机运行。

## 一人开发试玩

开发环境首页有明显标识的“开发试玩：一人切换三席”。创建的独立沙盒自动有三个角色。用顶部下拉切换席位，为每人选技能后切回房主开始。任务中切换角色，线索按当前视角显示。

- 沙盒不能让其他人加入，真人房不能代队友操作或切换视角。
- `.env` 中 `DEV_PLAY=false` 可关；`NODE_ENV=production` 无条件关，旧沙盒也不能连接。
- 开发试玩仅为验收便利，不是生产授权绕过。

## 完整规则（程序执行）

- 3人，每人初始5血、最高5血；开局各选一次性装备：抵消任务损伤、私人核对提示、自己回血。
- 7条本故事规则 → 团队按5个方向提交5个猜想。按固定事实轴计数，不少于3项不扣血，否则产生1血待协商损伤。只反馈正确数量，不显示哪些项命中。
- **非任务试错**：任何有血量者可提名承担者；只有被提名者本人可确认，明确扣1血。拒绝/30秒超时不扣血，保留团队试错债务以便重新提名。处理前暂停新试错，避免无限免费猜。线索交流仍可进行。
- **单人任务**：3次安全操作各得1张私密线索，错误扣搜证者1血。隐藏蓝纸补给额外1张，恢复发现者1血，只能发现一次。
- **双人任务**：一人“开始/停止测试信号”，服务端记录1—15秒，按四舍五入秒数判定；另一人仅获秒数末位，报完整时长。3次错误扣报时员1血；成功得1张私密音轨线索，共3张。测试超16秒自动截断15秒。不支持客户端指定时间或耗时。
- **兜底明确采用3血**：每个任务累计实扣3血，直接发该任务全部3张基础线索（技能抵消的不算实扣）。若单人零血或双人组全零，也发应急包防死锁；全队零血优先直接失败。双人仅一位有血量，系统发明确7秒应急信号让幸存者继续，不要求零血队友操作。
- 零血不再搜证、计时、猜测、用装备或承担损伤，但可看手牌、公开和组合。全员零血失败结算。
- 基础线索共6张；卡面标注可关联卡片ID。双方公开后组合生成新的共享推论卡。
- 两条任务完成 → 团队自由文本还原真相。固定6个关键事实，程序按覆盖数给：0—1毫无头绪，2—3初见端倪，4—5接近真相，6一语中的。不是让模型随意评心情；未完整需确认1血再重试。全部6项覆盖获胜。
- 主持人真相只在服务端和结算解封；未公开手牌只推给所属身份。

## AI 配置与隐私

复制 `.env.example` 后，**只有在你明确愿意把游戏证词和已公开线索发给所选服务时**才填：

```dotenv
AI_ENABLED=true
AI_BASE_URL=https://YOUR-PROVIDER/v1
AI_API_KEY=YOUR-OWN-KEY
AI_MODEL=YOUR-MODEL
AI_TIMEOUT_MS=10000
```

不提供、寻找或复用其他项目的密钥；不读取用户凭据目录。不使用 `VITE_*` 保存密钥。程序不打印密钥、请求正文或服务错误正文，前端不含凭据。

- 后端 adapter 调用 `/chat/completions`，要求JSON、Zod校验、超时中断。
- 语义标注器只返回白名单事实ID与玩家原文证据片段；按ID去重后由程序评分。玩家文本作为独立不可信数据，系统提示禁止改规则、索取底稿与服从注入。
- 氛围叙述只拿已公开线索与通用事件，不拿未解锁线索和真相。首次接线会有一句LLM氛围旁白，核心行动提示始终由程序给定。
- 模型拒绝、网络失败、坏JSON、坏schema时：**暂停本次判定、存下原文、不扣血**。玩家可原文重试，或明确选择“本次改用离线关键词判定”。不会把API故障伪装成玩家推理错误。
- 默认离线匹配按句检查关键词，否定句保守不计；灵活同义表达可能漏判，矛盾复杂句也不是完整逻辑证明。它是可测通流程的本地练习模式，不是最终语义裁判。

## 文件与边界

```
src/              前端、公开数据类型，不含谜底和未获线索
server/story.ts   仅后端：完整原创故事、线索、固定6事实
server/game.ts    状态机、权限、装备/血量、兜底、幂等
server/ai.ts      后端AI适配器
server/app.ts     HTTP/Socket身份验证、串行房间队列、持久化
server/HOST.md    主持人私有底稿（剧透，勿作为静态资源）
tests/            规则单测、三客户端联机、重启、AI模拟服务
```

`data/*.json` 保存房间、证词与身份令牌哈希；目录0700、文件0600、原子写入，已gitignore。不保存令牌明文。浏览器令牌位于localStorage。文件只适合单Node进程，不要多实例共写。

Vite开发文件访问明确禁用 `server/`、`tests/`、`docs/`、`data/`、`.env*`、`.git/`，防止有人直接请求剧本源码；生产只静态服务 `dist/`。游戏不会通过公共状态发送事实ID、真相、其他人手牌、令牌哈希和计时开始/精确耗时。

## 已知限制 / 发布前必须做

- 本版未连接真实AI、未部署、未购买任何服务、未通过图形浏览器做视觉/无障碍验收；已做非GUI自动化。
- 模型即使输出合法JSON仍可能语义误判；提示注入防护是降风险，不宣称绝对安全。需要实选模型后的中文证词回归、矛盾句/反事实对抗测试和人工剧本试玩。
- 故事是一个短篇首版，目标约30—45分钟，未做真人节奏与难度平衡；初步猜想本来允许证据不足，消耗一次容错。小游戏是启动/停止信号的简化版本，没有真实音轨识别、声音素材和内置聊天。
- 无账号、踢人/换人/房主迁移、房间列表、游戏中补位、跨设备身份恢复、离线队友替补。连接令牌等同席位钥匙。队友长期掉线时可等待重连，不能擅自替对方承担损伤；不保证人员退出后还能打完。
- 本地文件持久化无版本迁移、数据库事务或多实例锁；幂等ID随房间保存，单进程按房间串行，不是分布式系统。异常磁盘写入目前会报错，正式发布需可回滚事务/数据库。
- 启动忽略超过7天的存档（不删除文件）。房间内存上限200，没有完善自动清理/运营后台。简单限流不等于公网抗滥用。
- HTTPS、反代、备份、访问控制、安全审计、付费额度/AI成本控制、监控需在部署前落实。不应把开发Vite或JSON存档暴露公网。
- 当前npm audit报告开发构建链4个high（picomatch ReDoS传递至fdir/tinyglobby/Vite，GHSA-fc5q-39xc-vjpf；注册表最新picomatch仍4.0.7，暂无可用修复版本）。生产依赖审计为0。未使用 `--force` 降级至旧Vite；本项目不接受用户glob模式，仍需跟踪补丁，正式公网发布前重审依赖。
